# xy-goal 按本质重写：设计

日期：2026-10-03。来源：用户原话（契约 `~/.claude/xy-goal/20260923-022357-cf1m-cost-model-for-lp.md` 原话 533～536）：拆契约过线是作弊、5000 字够记所有重要的东西；按 skill 的本质做优化、整体符合三条铁律；要能发现「能派却没派」的事，而且要做进 skill 与代码、不靠记忆。

## 问题

xy-goal 现行版（`313b827`）在 2026-10-03 一天里暴露三件事：

1. **契约膨胀**：14 条在办，每条写到 450～500 字（判据抄进设计细节，产物栏夹着过程），清单部分涨到 7360 字。「已验收」「已取消」行只增不减，也挤占同一份预算。
2. **为了压字数叠出一套重机制**：改判据前存档、写草稿、派子代理核对、通过才换入、「自上次核对以来已存过就不再存」……当天四次核对里三次被细节驳回，维护契约的时间比推进目标还多。最后 skill 里「该清名单或拆目标」一句给了口子：契约拆成两份、各自压线，总数照样超。
3. **能派没派**：14 条在办，后台只有三四个子代理；一盘点，6 件可以当场派出却没人动。现行 skill 只管「别停下」「别自判完成」，不管「每件事有没有人在推」。

## 本质

xy-goal 存在，是因为一个跨会话的长目标会被执行者自己的四种毛病拖垮：

| 毛病 | 机制 |
|---|---|
| 上下文压缩、换会话后忘了要求 | 契约落盘，作为执行者与验证者共享的同一份事实 |
| 做到一半停下，或在办的事没人推 | 定时自查：每次都核真实状态、把能推的推出去 |
| 自己判自己做完 | 子代理按用户原话验收，验过才算 |
| 转述时把要求滤掉或放宽 | 用户原话照抄，作为权威 |

**每条规矩都要追到这四样之一，追不到的删。**

## 决定

**D1 原话是权威，判据是索引。** 原话照抄、不计字数、不压缩；三类标注（落条目／规矩：写在哪／无：为什么）不变；用户新来的话先照抄、标好落点，再去想和做。判据是从原话归纳的「怎么算做完」，日常可直接改写（压措辞、改正、按用户改口换成最新口径），不存档、不写草稿、不单独派人核对——验收者按出处回原话找齐要求再核，丢掉或放宽的在验收时被抓住；关闭时再拿全部原话总核。**例外**：一次改写多条（迁移、合并、换格式）时，改前存一份到 `archive/`，改后派子代理拿存档与原话核对没丢要求、没放宽，过了才算数。没做完的条目不许删；放宽判据只能凭用户原话。

**D2 契约只放在办的事。** 清单里只有 `[ ]`（在办）与 `[x]`（做完待验收）。验收通过的、用户明确取消的，当场移进同目录账本 `<契约名>.done.md`；账本每行必须是 `- <ID> <一句话>（…；验收 <报告路径>）` 或 `- [~] <ID> <一句话>（原话 N：「摘句」）`，由脚本检查，在办的事藏不进去。关闭时契约删掉，账本移进 `archive/` 留底。

**D3 预算按会话算总量。** 一个会话只有一个目标、一份契约、一个定时器；契约头写 `session: <会话 id>`。每条（标题与判据、出处、产物三行合计，不含末尾空行）≤ 300 字；同一 `session` 的所有在办契约清单部分合计 ≤ 5000 字。脚本按 `session` 分组求和，拆文件不会让计数变小，别的会话的目标也不会被算进来。超了只有一个办法：把条目压回规范、把做完的送验移走；不拆契约、不另建定时器、不调线。

**D4 条目写法与「谁在动」。** 四行：标题一句；判据＝怎么算做完（可核实、要求一个不少、不写怎么做）；出处＝原话编号或「来源：…」（我自己加的先问用户）；产物＝谁在动＋指针＋还差什么。`[ ]` 的产物以 `在跑：<子代理或后台任务名>（pid <进程号>）` 或 `等：<条目 ID 或「用户：要定的事」>` 开头，`[x]` 以 `待验收：` 开头。主会话不算推进者，只编排；能派的派给子代理，否则写「等：…」，检查器会拒绝把运行本检查会话的主会话 PID 登记为推进者。`在跑：` 每项都写成 `在跑：<名字>（pid <进程号>）`；`check.py` 用 `os.kill(pid, 0)` 核它还活着，`PermissionError` 视为活着，进程已不在就当场收尾、送验或重派。脚本还核：`等：` 指的条目确实还开着（指向已关闭的就是阻塞已解除、该动了）；写不出谁在动，就是该派没派。设计、过程、证据写进仓库或报告；指针必须指向能活到验收的地方，要被删的先改指新家。

**D5 自查做四件事，按这个顺序。** ① 跑检查脚本，把它报的问题当场改掉；② 逐条核真实状态（看文件、跑命令），核 `在跑：` 的都还活着；③ 每条答谁在动：能派的当场派出，用户批了的改动当场派人起草；④ `[x]` 送验，新冒出来的事追加。

**D6 检查脚本 `check.py`。** 零依赖 Python，放在 skill 仓里，必须显式给目录：`python3 check.py <契约目录>`（不给参数报错）。只看目录顶层的 `*.md`（不含 `archive/`、`*.done.md`），按 `session` 分组；输出：每组清单字数／5000；超 300 字的条目；`在跑：／等：／待验收：` 缺失或 `等：` 指向不存在、已关闭的条目；原话标注与出处对不上（区间 `113～115` 展开；原话正文里出现「（原话」字样不算标注）；账本格式错；模板格式错（缺 `cron_job_id:`、`session:`、`## 清单`、`## 用户原话`）。`在跑：` 每项都写成 `在跑：<名字>（pid <进程号>）`；`check.py` 用 `os.kill(pid, 0)` 核它还活着，`PermissionError` 视为活着，进程已不在就当场收尾、送验或重派。逐条 `<文件>:<行号>: <问题>`，有问题退出 1，没问题打印各组汇总并退出 0。

**D7 验收与关闭。** 验收：派子代理，清单与原话让它自己从文件读、核产物本身（读文件、跑命令、看 diff）、按出处回原话找齐要求、逐项给结论加证据；超时、报错、漏审一律重派，「不知道」不算通过。裁决权在我，驳回写进那条的产物栏并给可复核的理由；验不了不算做完，该我去补验。验收通过：条目移进账本；同一次验收由验收者判断哪些原话的落点已全部验收或已成取消、意思确实被覆盖，可删。关闭：剩下的全部送验，并让验收者拿全部原话核整体结果（有没有少记、账本里的产物有没有被后来的改动弄坏）；回溯本会话的盲区（说过待会儿再做的、顺手发现没记的、用户中途改口的），补进清单重验；`CronDelete` 确认成功后汇报，契约删掉、账本进 `archive/`。

**D8 定时器。** 间隔从 10／15／20／30 里选（整除 60，首次落在 k 分钟后）：多在等后台选 30，一直有活可推选 10，其余 15 或 20。以当前分钟 `m` 计算 `(m + j×k) mod 60`，`j = 0 … 60/k−1`，将分钟值升序排列。例如 12:50 建、`k=15`，表达式为 `5,20,35,50 * * * *`，首次触发在 13:05。提示词写自查与检查脚本的调用（主目录 `~/.claude/skills/xy-goal/check.py`），内容须能独立执行：先读绝对路径的契约，逐条查看文件并运行命令核实产物真实状态，不靠记忆；未完成的接着做，能派的当场派出，再送验 `[x]` 并追加新工作。建好回填 `cron_job_id`、`CronList` 核对只有这一个；告诉用户间隔、只活在本会话、7 天过期、空闲时才触发。skill 改版后先按新文案建新定时器、回填、核对，再删旧的。

**D9 迁移在用的契约（skill 合入之后做）。** 改前整份存档；「已验收」行、它引用的存档、`[~]` 行按 D2 的格式移进账本；条目压回 ≤ 300 字；产物栏按真实状态写 `在跑：／等：`，能派的当场派出；补上 `session:`；跑通检查脚本；按 D8 重建定时器；按 D1 的例外派子代理核迁移。

**触发边界不变：** 只在用户或文档明确要求使用 xy-goal 时调用。
