# xy-goal 按本质重写：设计

日期：2026-10-03。来源：用户原话（契约 `~/.claude/xy-goal/20260923-022357-cf1m-cost-model-for-lp.md` 原话 533、534、535）：拆契约过线是作弊、5000 字够记所有重要的东西；按 skill 的本质做优化、整体符合三条铁律；要能发现「能派却没派」的事。

## 问题

xy-goal 现行版（`313b827`）在 2026-10-03 一天里暴露三件事：

1. **契约膨胀**：14 条在办，每条写到 450～500 字（判据抄进设计细节，产物栏夹着过程），清单部分涨到 7360 字。「已验收」「已取消」行只增不减，也挤占同一份预算。
2. **为了压字数叠出一套重机制**：改判据前存档、写草稿、派子代理核对、通过才换入、「自上次核对以来已存过就不再存」……当天四次核对里三次被细节驳回，维护契约的时间比推进目标还多。最后 skill 里「该清名单或拆目标」一句给了口子：契约拆成两份、各自压线，总数照样超。
3. **能派没派**：14 条在办，后台只有三四个子代理；一盘点，6 件可以当场派出却没人动。现行 skill 只管「别停下」「别自判完成」，不管「每件事有没有人在推」。

## 本质

xy-goal 存在，是因为一个跨会话的长目标会被执行者自己的四种毛病拖垮：

| 毛病 | 机制 |
|---|---|
| 上下文压缩、换会话后忘了要求 | 契约落盘，作为执行者与验证者共享的同一份事实 |
| 做到一半停下，或在办的事没人推 | 定时自查：每次都核真实状态、把能推的推出去 |
| 自己判自己做完 | 子代理按用户原话验收，验过才算 |
| 转述时把要求滤掉或放宽 | 用户原话照抄，作为权威 |

**每条规矩都要追到这四样之一，追不到的删。**

## 决定

**D1 原话是权威，判据是索引。** 原话照抄、不计字数、不压缩；三类标注（落条目／规矩／无）不变。判据是我从原话归纳的「怎么算做完」，随时可以改写（压措辞、改正、按用户改口换成最新口径），**不存档、不写草稿、不单独派人核对**——验收者按出处回原话把要求找齐再核，丢掉或放宽的在验收时被抓住；关闭时再拿全部原话总核一遍。删掉「改前存档 → 草稿 → 核对 → 换入」整套机制。

**D2 契约只放在办的事。** 清单里只有 `[ ]`（在办）与 `[x]`（做完待验收）。验收通过的、用户明确取消的，当场移进同目录的账本 `<契约名>.done.md`，一条一行：`- ID 一句话（产物；验收报告路径）` 或 `- ID 一句话（取消：原话 N「摘句」）`。契约不再留「已验收」「已取消」两段。

**D3 预算是一个目标的总量，由脚本数。** 每条（四行合计）≤ 300 字；清单部分合计 ≤ 5000 字。一个目标只有一份契约、一个定时器；检查脚本对 `~/.claude/xy-goal/` 下所有在办契约求和，拆文件不会让计数变小。超了只有一个办法：把条目压回规范（判据一句、产物一句）、把做完的送验移走；**不拆契约、不另建定时器、不调线**。

**D4 条目写法。** 四行：标题一句；判据＝怎么算做完（可核实；要求一个不少；不写怎么做）；出处＝原话编号或「来源：…」；产物＝**谁在动**＋指针＋还差什么。「谁在动」写在跑的子代理／后台任务名，或真实阻塞（等用户哪个决定、等哪件事的哪个产物）；写不出就是该派没派。设计、过程、证据写进仓库或报告，契约只放指向它们的路径；指针必须指向能活到验收的地方。

**D5 自查做四件事，按这个顺序。** ① 跑检查脚本，把它报的问题当场改掉；② 逐条核真实状态（看文件、跑命令，不靠记忆）；③ 每条答「谁在动」：能派的当场派出（两个号都可并发），批了的改动当场派人起草 spec；④ `[x]` 送验，新冒出来的事追加。用户新来的话先照抄进原话、标好落点，再去想和做。

**D6 检查脚本 `check.py`。** 零依赖 Python，放在 skill 仓里，`python3 check.py`（不带参数＝检查全部在办契约）输出：清单总字数／5000；超 300 字的条目；产物栏缺「谁在动」的条目（按约定的前缀判）；原话标注与出处对不上处（区间写法如 `113～115` 展开）；模板格式错误。有问题时退出码非 0。规矩能写成检查的都写进脚本，SKILL.md 不再复述脚本已经保证的事。

**D7 验收与关闭不变的部分。** 验收：派子代理，清单与原话让它自己从文件读、核产物本身、按出处回原话找齐要求、逐项给结论加证据；验不了不算通过；裁决权在我，驳回写进那条的产物栏并给可复核的理由。验收通过：条目移进账本，同时由验收者判断哪些原话的落点已全部验收、可删。关闭：剩下的全部送验＋拿全部原话总核＋回溯本会话的盲区＋`CronDelete`；契约删掉，账本留着。

**D8 定时器。** 间隔规则不变（10／15／20／30，整除 60、首次落在 k 分钟后）。提示词只写自查四件事与检查脚本的调用，细节回 SKILL.md 找；skill 改版后删掉旧定时器、按新文案重建。

**D9 迁移在用的契约。** 现有契约按新格式迁：「已验收」「已取消」行与它们引用的存档移进账本；每条产物栏补上「谁在动」；跑通检查脚本；定时器按新文案重建。

3. 在用契约按 D9 迁完，`check.py` 对它退出码 0，定时器已按新文案重建。
