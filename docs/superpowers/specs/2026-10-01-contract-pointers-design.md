# 契约只放判法与出处：通用指示进记忆，字数线 5000

日期：2026-10-01。只动本仓 `SKILL.md`（`README.md` 涉及时同步）。spec 与计划在收尾时删除。

## 问题

用户原话（2026-10-01）：「我感觉 1 万多字其实已经能表达非常多的信息了，这个信息量我觉得非常过载」；看到 21 段通用原话永远退不了场后：「这说明我们的规矩有问题……你要根据铁律来优化它」。决定权交给 main，要有依据。

在用的那份契约当时的构成（全文约 2.57 万字）：

| 部分 | 字数 | 病因 |
|---|---|---|
| 我写的部分 | 12,256 | 见下三行 |
| 　未完成条目的判据 | 5,227 | 抄了设计内容：一条 1,260 字，把整套设计复述一遍，而 spec、代码、原话里各有一份；用户改口后旧说法还留在判据里，只能再追加一句打补丁 |
| 　未完成条目的产物 | 2,781 | 夹着过程记录 |
| 　已取消条目 | 2,077 | 每条带长引文 |
| 用户原话 | 13,818 | 用户自己打的 6,510、选中的选项文字 3,379、我加的标注 3,929；其中 21 段（2,669 字）挂在「全部未完成条目」上，退场条件「指到的条目都已验收」永远不成立 |

两条根因：

1. **拷贝代替指针**。判据被写成「设计内容的副本」。副本会过期，过期就和正本矛盾；「判据只能往后加」又让过期的字删不掉。
2. **工作方式混进了目标**。「用 codex 别用 deepseek」「自查时附搜索结果」这类话是怎么干活的规矩，不是这个目标的交付物，挂在「全部未完成条目」上只能永远留着。

外部做法（联网查过）：Anthropic 长任务 harness 的任务清单每条只有「一句描述、几步验证、是否通过」，agent 只许改「是否通过」；Anthropic 上下文工程：「找能最大化目标达成概率的最小高信号 token 集」；Claude Code 官方最佳实践：「每一行都问：删掉它会让 Claude 犯错吗？不会就删」；HumanLayer：「放指针，不放拷贝」。

## 决定

| # | 决定 |
|---|---|
| D1 | **一条未完成条目 = 标题一句 + 判据 + 出处 + 产物**，以 300 字为度。判据只写怎么判完成（可核实）；出处写原话编号与 spec／文档路径；产物写现状指针与还差什么。**设计内容不进契约**：它在 spec、代码、文档与原话里，契约只指过去。 |
| D2 | **判据的改动**：用户新原话带来新要求，出处加编号、必要时判法加一句；用户改口，判法改成最新口径、出处加编号。凡是删字或改写，照旧走「清理」第 4 步（存原文、写草稿、子代理核对没丢要求、没放宽）。「判据只能往后加」这句删掉：它要守的「不许悄悄放宽」由子代理核对守住，不靠只增不减。 |
| D3 | **原话的标注只剩三类，去掉「全部未完成条目」**：① 带目标要求的 → 落到条目；② 工作方式类的通用指示（怎么干活、用什么工具、汇报什么格式）→ 当场写进持久的工作规矩（记忆、CLAUDE.md 或对应 skill），标「（原话 N → 规矩：<写在哪>）」；③ 提问、确认、命令展开（如某个 skill 的固定展开文字）→ 标「→ 无」，命令展开只记一行、不抄展开文字。②③ 在下一次送验时由子代理核对（规矩确实写进去了／确实不带要求）后删。 |
| D4 | **已取消条目只留一行**：「- [~] ID 一句话（原话 N：「不超过 30 字的摘句」）」。摘句就是取消的凭据，原话那段随后可按 D3 的流程删。 |
| D5 | **字数线 5000**：我写的部分（「## 用户原话」之前）达到 5000 字就在那次自查里做完整清理（原来 12000）。依据：10 条左右在办的事 × 300 字 + 头部与已验收约 1000 字 ≈ 4000，留五分之一余量。用户原话不计入、不压缩；有了 D3，原话只剩指向未完成条目的那些。 |
| D6 | **自查 prompt 同步**：12000 改 5000；标注检查里「全部未完成条目」不再是合法目标，「→ 规矩：」是新的合法标注。已经在跑的定时器由用它的会话按新 prompt 重建，skill 只写一句提醒。 |
| D7 | **skill 自身按铁律压**：判据那段长句拆短、删重复说法；规则只说一遍。 |

不做：不加脚本或工具；验收与关闭的流程不动。
